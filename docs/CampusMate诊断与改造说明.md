# CampusMate 2.0 诊断与改造说明

本轮在收到的`freshman-guide-2026-10-15.2/freshman-guide-2026-10-15-campus-update`副本上工作。桌面原件保持原样，未用从零重写替换已有实现。记录日期：2026-11-01（Asia/Shanghai）。

## 审查结论

实际运行入口为`run.py → backend/main.py`，基于Python标准库HTTP服务及SQLite；前端为原生HTML/CSS/JavaScript。README中的旧Streamlit/FastAPI/Chroma实现已经不在启动路径上，相关依赖文件不代表当前需要安装。保留现有架构可避免引入新的环境和迁移成本。

原项目拥有19份本地资料、235个文本块、BM25检索、可选DeepSeek生成、SSE分段回答、来源展示、反馈、清单、成长推荐、个人任务、演练、校园探索行程及准备台。原有82项测试在改造前通过。主要不足为：学校资料/地图/咨询入口绑定河职大；数据库只有浏览器会话隔离；备份缺少学校归属；所谓联网功能只是手动核对链接；地图依赖交接图片；缺少针对个人情况的报到任务生成。

安全方面，原实现已经默认关闭AI，禁止使用交接密钥指纹，避免直接暴露.env，校验本机Host/Origin并限制静态文件路径。本轮保留这些措施，新增独立搜索密钥、固定搜索接口、官方域名校验和禁止搜索重定向。未调用真实密钥、未查询余额，未新增伪造的开发Prompt或历史提交。

## 数据流与边界

浏览器请求携带`school_id`或`X-CampusMate-School` → 注册表精确匹配 → 该校Application → 该校Retriever/Answerer/Store。多处标识不一致或不在注册表中时拒绝请求，不将标识拼接为任意文件路径。

每校数据库位于`GUIDE_DATA_DIR/schools/<school_id>/guide.sqlite3`，因此消息、反馈、偏好、收藏、清单、个人任务、演练和准备台都在独立数据库内；原有session隔离继续有效。按学校分库是数据组织机制，学校选择不是账户认证，不能作为公网多租户授权实现。请求频率预算按进程/IP共用，切换学校不会增加额度。

本地索引只由本校的清单加载。`hnvust`兼容读取原根目录的19份交接资料；空白模板索引为空，其他学校不能通过`legacy_content`借用原资料。新下载文件要求路径位于本校目录、来源位于本校官方域名、实际SHA-256匹配；待补充条目不入库。原交接文件的“官方已核实”标签不被当成本轮重新核验结果。

联网增强使用两个工作线程同时执行本地检索和Brave搜索API。发送的搜索词由学校名、官方域名和固定主题词组成，不发送完整问题、前文、session或个人偏好。结果最多保留3条本校HTTPS官方域名摘要；这会漏掉官方域名之外的真实公众号或政府信息，但能避免无约束抓取和错校污染。没有官方域名的学校不发搜索请求。

联网摘要记录原始URL、搜索服务提供的标题、可用发布日期（缺失不推测）、检索时间、所属学校与“正文未核验”提示。不会自动下载搜索结果，不把官方域名摘要标记成已验证学校规定。金额/日期/年份差异仅产生待核对提示，不自动选择“最新事实”。当年安排缺失时保留未知状态。搜索可用性与AI是否开启分别呈现，AI密钥不能启用联网。

## 地图与个性化任务

SVG由代码直接生成，包含二维建筑、树木、水面等示意元素；位置复用交接图上的百分比，非实际测绘。装饰线不代表道路，探索连线只是访问顺序。未使用AI图片工具生成“真实校园”素材，未声称校方授权或官方地图。原始照片和地图仍保留在项目内。

任务生成仅使用是否计划住校、是否希望了解资助、是否跨城出行及自填日期，不收集身份证或家庭证明。先预览，确认后加入原有任务系统；单次生成保持100项上限并原子写入。每种生成模板按session记录，重复生成保留已有任务状态和日期；不会自动勾选报到完成。独立生成标记不随旧通用任务备份迁移，因此在新会话中恢复普通任务备份后，需检查是否已包含相同建议，再决定生成。

旧单校数据库可通过`tools/migrate_legacy_data.py`显式只读备份到hnvust子目录。目标存在时不覆盖；不会自动猜测旧数据归属。测试中发现SQLite连接上下文不会自动关闭文件句柄，已增加显式关闭，修复Windows临时文件锁问题。

## 官方材料处理

本轮使用网页检索核实了[河南科技职业大学2026年招生章程](https://www.hnvust.cn/info/1036/3851.htm)的官方域名、实际标题和2026-05-18发布日期。执行环境拒绝本地网络下载，自动审批规则也拒绝提高权限执行该下载。因此未产生已下载正文文件，`knowledge/hnvust/sources.json`标记`verified_url_pending_download`，`downloaded_at/file/sha256`均为null。

未找到并核验完整的2026级新生入学须知或可用于本次产品的官方地图文件。相应来源清单条目标记待补充；没有从其他学校网站下载相似文件充数，没有编造报到日期、接站安排、材料规格或实地路线。招生章程的存在不等于报到事项已确认。

## 后续接入顺序

1. 由学校公开资料核实并补充当年入学须知与实际报到安排，按来源清单归档、复核，再启用相关规则。
2. 对照校方地图/实地资料核验各热点和图像许可，区分校区；在核实前保留插画示意标记。
3. 接入第二所真实高校时先完成独立知识、学校配置与地点验收，再按本校资料适配宿舍/演练等模块。
4. 真实搜索服务配置后用自有密钥验证返回格式、覆盖率、超时和费用；本轮协议模拟测试不替代该步骤。
5. 若决定公网部署，再实施账户、权限、学校管理员内容审核、备份与运维，不直接把当前本机服务绑定公网。
